# Consolidated PicklePro application

This branch starts at RohitVer `picklepro-coaching` so its CV and annotation history remains visible. The application, session flow, and player reporting descend from KirkVer. The KirkVer questionnaire wizard is restored here. There is one Vite application, one Python analysis pipeline, and one versioned result contract (`server/picklepro/contract.py`, its TypeScript mirror, and generated JSON schema). No database migration is required: confirmed court points use the existing analysis job `params` JSON. No production deployment or live database change is part of this branch.

## Run locally

From `Pickleball Performance Dashboard/`, run `npm ci`, copy `.env.example` to `.env.local`, and run `npm run dev`. In another terminal, install `server/requirements.txt` into a Python environment, then from `server/` run `python -m uvicorn main:app --host 127.0.0.1 --port 8000`. Open `http://localhost:5173/#/local-prototype` for analysis without an account, or configure Supabase and a separate `python -m picklepro.worker` process for private saved Sessions. The application route `#/label` works locally without signing in. See [README](../README.md), [model setup](MODEL_SETUP.md), and [Supabase setup](SUPABASE_SETUP.md). Model discovery only finds local weights; it never downloads them during analysis.

The public trial is a previous deployment and does not run this branch. An HTTPS page also may not be able to reach a local HTTP preview service. A browser-only geometry check allows manual correction when that service cannot be reached, but the worker still rejects a correction that fails its painted-line check. A worker must be running for saved uploads to finish.

## Court correction

After choosing a video, pause on a frame with visible painted lines. The local preview service proposes named court landmarks using line fitting and the optional existing court model. Drag yellow points to correct them, or place at least four named points manually. The browser checks names, image bounds, and point spread. When reachable, the preview service also compares the corrected map to actual painted lines. Confirming saves `calibration`, `calibration_source: user_confirmed`, and `calibration_frame_s` in the analysis setup. The worker checks the source frame again before using the map and records `calibration.method: user_confirmed_landmarks` in the result. Samples before the confirmed frame do not receive that map.

This correction is for a fixed view. A later camera movement or cut invalidates it, and court measures stop using the map. Automatic court tracking still fits/refines painted lines as it analyzes frames and checks carried mappings. A correction that misses painted lines fails explicitly and is not retried as a transient analyzer error. In the saved session's **Re-run analysis** section, choose the same local video to correct the map again, or choose automatic mapping. Re-running with only a different player selection keeps the saved court setup. Weak or missing mapping produces `insufficient_data` for court metrics. A good reprojection fit only says the chosen points agree with one planar transform; it is not an accuracy measurement on players.

## Result interpretation

The pipeline groups fragmented player tracks and marks people mostly off court. Thumbnails help users choose themselves. Those are heuristic associations and can be wrong; selection for a saved report is reanalyzed against the chosen track and camera view. A selection in the local result view is a filter until reanalysis. Ball boxes retain time, model score, and `observation_kind: observed`; gaps are not filled. `provenance.ball_tracking` records candidate filtering counts, including oversized and static candidates. The score is model confidence, not measured accuracy.

`shot_type` retains RohitVer's richer experimental research categories. `public_shot_type` uses revision 4's serve, volley, dink, drive, and lob plus `unclassified`; return, drop, reset, speed-up, counter, overhead, and erne become **unclassified** in this public field rather than being silently relabeled. The player report withholds shot counts, shot panels, overlays, and personalized shot advice until a result is marked `evaluated_on_real_footage`. The local prototype explicitly opens the research view for inspection. Neither status is a claim of independent accuracy. Rally estimates remain experimental. Court-plane mapping cannot establish ball height or three-dimensional speed.

## Annotation and evaluation

Open `#/label`, choose a video, and optionally import an analysis result or an existing label file. Mark contact time frame by frame, assign person 1–4 independently of model tracking, select the shot type, and confirm each label. Suggestions from the model remain drafts and are excluded from downloaded labels until confirmed. `unclassified` stays unclassified. Add person descriptions and, if a result is loaded, explicitly map each human person to a tracker ID. The downloaded file marks `identity_scheme: human`; unmapped human IDs are excluded from the hitter accuracy denominator. Older files without that marker retain their legacy interpretation of `player` as tracker ID.

Run `python -m picklepro.evaluate result.json labels.json` from `server/`. Matching uses the nearest unused detection in each contact-time window, without preferring the predicted hitter. Frame-precise labels match within 0.35 seconds; old whole-second labels cover their second with 0.35-second margins. Unmatched labels reduce recall; unmatched detections reduce precision. The report separately shows matched type accuracy, mapped hitter accuracy, wrong-type pairs, and detections at explicitly marked `not_a_shot` moments. A missing hitter or an unmapped human ID is not counted as correct. Save development clips and labels separately from untouched final-test recordings, and fix thresholds only on the development set. The existing one-clip results used to tune rules are development checks, not independent validation.

## Remaining limits

Court and player tracking need clear footage and local models for useful results. Camera cuts can be missed, and human identity across views is not established. Fast or occluded balls are missed; stationary-look-alike filtering can also reject real observations. Shot events and types have not passed independent final-test evaluation. The next evaluation should use multiple consented recordings from distinct courts, lighting, viewpoints, and players, with frame-precise human labels and a held-out final set. It should report court mapping, player identity, ball precision/recall, hit precision/recall, hitter attribution, and confusion among the five revision 4 shot classes.

On one existing 51-second development clip, a full local smoke run decoded 512 sampled frames, kept a court map for 492, grouped five on-court tracks and one off-court person, retained 248 observed ball boxes, and proposed 11 shots. Visual spot checks at 0, 10, 25, and 45 seconds showed the projected court lines generally following visible paint when present, but missed near-side player boxes and clusters of ball candidates around players. Some inferred landing coordinates were far outside the court; the later shot-evidence branch withholds those implausible landings from shot travel estimates. The run had no selected player, so the court heatmap correctly returned `insufficient_data`. The existing whole-second development labels contain 26 hits; the revised time matcher paired 10 with proposals. These observations expose limitations and are **not** independent accuracy results. The old label file uses tracker IDs directly, so its hitter score must not be interpreted as person identity accuracy after track regrouping.
